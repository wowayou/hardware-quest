# 关卡格式

一关 = `levels/` 下的一个文件夹。加一关只需要加一个文件夹，不用改任何代码。
`npm test` 会校验所有关卡，格式不对会指出是哪一关的哪个字段。

```
levels/
  chapters.json            章节列表
  _template/               模板（下划线开头的文件夹不会被加载）
  01-closed-loop/
    level.json             元数据和答案
    level.md               正文（故事、知识点、任务、提示、复盘）
    circuit.txt            实验文件（按 level.json 的 lab.files 列出）
    solution/              参考解：修好之后的同名文件 + check.json（不在界面里展示，供检查脚本用）
```

关卡顺序 = 文件夹名的字典序，所以用两位数字前缀。调整顺序只改文件夹名，`id` 不变，玩家进度不丢。

## chapters.json

```json
[
  { "id": "basics", "title": "第一章 电从哪来，到哪去", "intro": "一两句话的章节引子。" }
]
```

## level.json

```json
{
  "id": "closed-loop",
  "chapter": "basics",
  "title": "不亮的台灯",
  "concept": "闭合回路",
  "card": "电流只在闭合的回路里流动：从电源正极出发，经过用电器，回到负极。",
  "lab": {
    "tool": "falstad",
    "files": ["circuit.txt"]
  },
  "answer": { "type": "number", "value": 9.7, "tolerance": 0.5, "unit": "mA" }
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 是 | 稳定的唯一标识，小写字母、数字、连字符。进度按它保存，**发布后不要改**。 |
| `chapter` | 是 | `chapters.json` 里的某个 `id`。 |
| `title` | 是 | 关卡名。 |
| `concept` | 是 | 这一关教的概念，一个短语。 |
| `card` | 是 | 过关后收进「图鉴」的知识卡，一两句话，纯文本。 |
| `lab.tool` | 是 | `falstad`（CircuitJS 模拟电路）、`wokwi`（单片机仿真）或 `none`（纯推理题）。 |
| `lab.files` | tool 不是 `none` 时必填 | 要交给玩家的文件名，都在关卡文件夹里。`falstad` 恰好一个 `.txt`（CircuitJS 导出的电路文本）；`wokwi` 必须含 `diagram.json`，通常还有 `sketch.ino`。 |
| `lab.board` | 否 | 仅 `wokwi`：新建工程用的开发板，默认 `arduino-uno`。 |
| `lab.url` | 否 | 仅 `wokwi`：这一关在 Wokwi 上已发布的公开工程链接（`https://wokwi.com/projects/<数字>`）。填了之后界面多一个「一键打开」按钮；不填时玩家照常复制文件。 |
| `answer` | 是 | 见下。 |

### answer

文本答案（口令）：

```json
{ "type": "text", "accept": ["CHIP"], "format": "4 个大写字母" }
```

比较前会做归一化：去掉首尾和中间的空白、全角转半角、不分大小写。`accept` 里任何一个匹配就算对。`format` 显示在输入框旁边，告诉玩家答案长什么样，可省略。

数值答案：

```json
{ "type": "number", "value": 3.3, "tolerance": 0.05, "unit": "V" }
```

玩家输入的数字与 `value` 之差不超过 `tolerance` 就算对。玩家带不带单位都行（只取开头的数字）。`unit` 显示在输入框旁边，可省略。

## level.md

用二级标题分节。节名固定，顺序随意：

```md
## 故事
今晚的活儿是什么。两三句话。

## 知识点
解这一关需要的概念。术语第一次出现时给出英文全称和一句话解释。

## 任务
玩家要做什么，做到什么程度会得到答案。

## 提示 1
最轻的提示：指方向。

## 提示 2
指出问题在哪。

## 提示 3
几乎说出做法（但不直接给答案）。

## 复盘
过关后才显示：为什么这样就对了，换到真实硬件上要注意什么。
```

| 节 | 必填 | 说明 |
|---|---|---|
| `故事` | 是 | |
| `知识点` | 是 | |
| `任务` | 是 | |
| `提示 N` | 至少 1 个 | 逐条揭开。全部揭开后玩家可以选择「看答案」，这一关会记为"看过答案"并放行。 |
| `复盘` | 是 | 过关或看答案后显示。 |

正文是普通 Markdown（由 `marked` 渲染），可以用列表、表格、代码块。代码块里以 `## ` 开头的行不会被当成分节。

## 写关卡的约定

- **答案要从硬件行为里来**：修好电路或代码之后，仿真器里看得到（串口输出、屏幕、读数、闪烁次数），而不是读起始代码就能抄到。口令在代码里要简单混淆一下（比如异或）。
- **起始文件能运行但得不到答案**：能编译、能仿真。要么有毛病等玩家修，要么需要玩家观察并解码。
- **`solution/` 必须真的能得到 `answer`**：用 `tools/` 下的检查脚本在真实仿真器里跑过（见下）。
- **Wokwi 关卡不用第三方库**：玩家是把文件粘贴进空白工程的，装库要多点好几步。只用 Arduino 自带的（`Wire`、`SPI`、`EEPROM`、`SoftwareSerial`、`Servo` 不算自带，别用）。
- **只教一个新概念**，前面关卡教过的可以直接用。
- 仿真器和真实硬件表现不同的地方，写进 `复盘`。

## 检查关卡

| 命令 | 做什么 | 要不要联网 |
|---|---|---|
| `npm test` | 校验所有关卡的格式（字段、分节、文件是否存在、id 是否重复） | 不要 |
| `node tools/check-falstad.mjs [关卡文件夹…]` | 在真实的 CircuitJS 里打开起始电路和参考解，确认参考解读得到答案、起始电路读不到 | 要 |
| `node tools/check-wokwi.mjs [关卡文件夹…]` | 在真实的 Wokwi 里跑起始工程和参考解，确认参考解吐出答案、起始工程不吐 | 要 |

后两个脚本用本机的 Chromium 打开仿真网站，只在改了关卡之后手动跑，不放进自动流程。`solution/check.json` 的写法见各脚本开头的注释。
